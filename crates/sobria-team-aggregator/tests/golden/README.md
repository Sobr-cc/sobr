# Golden files of the team server

These JSON files pin the **current behavior** of `sobria-team-aggregator` over HTTP
(SOB-10): status code, content type and body of the API endpoints, including the
refusals, and the privacy rules on aggregates (k-anonymity, ADR-0015; visibility
policies, ADR-0016). They are read by `tests/characterization_*.rs`.

- Each test starts a real HTTPS server and records every response in order.
- Employees and estimations are seeded straight in the database with fixed ids
  (`01HZ…`) and fixed timestamps (May 2026), so the numbers are fixed and stay
  readable in the files.
- Values the server generates at random are checked for their shape, then replaced
  by a placeholder. A value of an unexpected shape fails the test.
  - ULIDs generated by the server: `<ulid#1>`, `<ulid#2>`… (numbered by first
    appearance in the file)
  - enrollment codes: `<code#1>`…
  - clock timestamps (`created_at`, `expires_at`, `last_seen_at`…): `<timestamp>`
  - access and refresh tokens: `<jwt>`, `<refresh_token>`
  - the crate version: `<crate_version>`
- Position suffixes of JSON parse errors (" at line N column M") are removed: they
  depend on the key order, which depends on the features other crates enable.
- Numbers are compared with a relative tolerance of 1e-9; everything else is exact.
- A failing test means the behavior of the server changed. That is not always a bug:
  an intended change is accepted by regenerating the files **and saying so in the PR**.

Regenerate, only if the change is intended:

```bash
SOBRIA_UPDATE_GOLDEN=1 cargo test -p sobria-team-aggregator --no-fail-fast \
  --test characterization_auth --test characterization_user \
  --test characterization_privacy --test characterization_admin
```

```powershell
$env:SOBRIA_UPDATE_GOLDEN = "1"
cargo test -p sobria-team-aggregator --no-fail-fast --test characterization_auth --test characterization_user --test characterization_privacy --test characterization_admin
Remove-Item Env:SOBRIA_UPDATE_GOLDEN
```

A test that rewrites a file **fails on purpose**, so that a variable left exported
cannot hide a regression: run again without it to check, then read `git diff`.
Only the value `1` rewrites, and it is refused when `CI` is set. If a test is
renamed, delete the old `.json` file by hand: nothing detects an orphan file.

## What is not pinned

- The CSRD export is a PDF: only its header and its size are checked.
- The e-mail notifications of the alerts are not sent (no SMTP in the tests); the
  trigger rows and the `notify_error` they carry are pinned.
- Some settings are refused by the `config set` command (`k_anonymity_min` under
  its floor or unreadable, a visibility policy of an unknown value, `identified`
  without its attestation). The tests write them straight in the database to pin
  how the server reads them.

These tests do not say whether a behavior is **right**, only that it did not move.
A behavior that looks wrong is pinned as it is and filed as a separate issue; it is
not fixed here.
